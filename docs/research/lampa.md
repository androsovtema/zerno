## 1. Что это за продукт

- [факт] Камера для iPhone, App Store id6478854930, категория Photo & Video, iOS 17+, только iPhone. Разработчик — Alexey Teplonogov, соло; по X/LinkedIn — iOS-инженер, раньше работал в Prisma.
- [факт] Позиционирование: «честные» натуральные снимки без HDR, ИИ и искусственной резкости. Камера снимает RAW и сразу проявляет его через профили «под плёнку и цифромыльницы». Профили и экспозицию можно менять после съёмки (redevelop), RAW можно экспортировать.
- [факт] Видео до 4K/60 с цветокоррекцией профилем и динамическим зерном. «Полностью натуральное» видео — только на iPhone с Log (15/16/17 Pro).
- [факт] Импорта из галереи нет: разработчик объясняет, что приложение работает только со своим RAW. Видоискатель — приближение к итогу (тоже слова разработчика в ответах на отзывы).
- [факт] Монетизация: бесплатно 5 снимков в день и ограниченные профили. Подписка: $4.99/мес, $29.99/год (есть и $19.99/год), lifetime $59.99, Season Pass $9.99. Пробный период 7 дней.
- [факт] Метрики с сайта: 440k+ загрузок, 2 700+ оценок, 4.7★. В US App Store — 354 оценки, 4.7★.
- [факт] Темп разработки: версия 2.0 с видео — февраль 2026, затем релиз каждые 2–4 недели (последний 2.2.1 — ноябрь 2026).
- [факт] Android-версии нет.

### Отзывы (App Store)

- Хвалят: сам «плёночный» вид снимков, простоту, скорость, дизайн.
- Ругают: лимит 5 фото в день (и когда он сбрасывается), цену около $30 в год, бедное редактирование (только экспозиция), нет импорта, видоискатель не совпадает с итогом, автофокус в видео, нет быстрой кнопки 2x и таймера. Были баги: фото не сохранялись, фронталка на новых iPhone.

## 2. Как это, вероятно, устроено на iOS [вывод]

Исходники закрыты. Ниже — реконструкция по описанию и по возможностям iOS.

| Слой | iOS (вероятно) | Аналог на Android |
|---|---|---|
| Захват RAW | AVCapturePhotoOutput: Bayer RAW / ProRAW | Camera2 `RAW_SENSOR` + `DngCreator`; CameraX 1.5+ (DNG и DNG+JPEG) |
| Проявка RAW | Core Image `CIRAWFilter` (демозаик, баланс белого, матрицы) | Готового нет. Свой GPU-пайплайн (OpenGL ES 3.1 compute / Vulkan) или LibRaw через NDK |
| Профиль | Metal: тон-кривая, цветовая матрица / 3D LUT, зерно, halation | Те же шейдеры на GLSL; профиль = 3D LUT + параметры |
| Превью | Аппроксимация профиля на живом потоке | CameraX `SurfaceProcessor` / GL-шейдер на YUV |
| Видео | Apple Log → LUT + зерно в Metal | Публичного Log API нет (см. ниже); 10-bit HLG (Android 13+) или SDR без обработки + GPU-грейдинг |
| «Без обработки телефона» | RAW обходит Deep Fusion и Smart HDR | RAW обходит ISP; для YUV/JPEG есть `NOISE_REDUCTION_MODE_OFF`, `EDGE_MODE_OFF`, `TONEMAP_MODE_CONTRAST_CURVE` |
| Оплата | StoreKit | Google Play Billing |

## 3. Особенности Android: что сложнее, что проще

Сложнее:
1. **Фрагментация RAW.** RAW доступен только камерам с hardware level FULL/LEVEL_3 и capability RAW, причём отдельно для каждого модуля: основной может уметь, телевик — нет. На бюджетных устройствах RAW часто нет совсем → нужен fallback-путь через YUV.
2. **Нет готового RAW-проявщика** уровня `CIRAWFilter` — это главный объём работы. Берём из метаданных DNG: black/white level, `AS_SHOT_NEUTRAL`, `COLOR_TRANSFORM`/`FORWARD_MATRIX`, lens shading map.
3. **Log-видео.** У Samsung Log есть (S24/S25/S26, Fold/Flip 6–7), но [факт] документированного API для сторонних приложений нет — только родная камера. Blackmagic Camera, по словам пользователей на форуме, строит свой Log из RAW-потока Camera2; это очень тяжёлая задача.
4. Разные сенсоры дают разный «характер» → нужна калибровка и тесты на 5–10 популярных моделях.

Проще или есть преимущество:
1. Матрицы цвета из DNG переводят camera RGB в стандартное пространство (XYZ). Значит, профиль можно писать один раз в стандартном пространстве, и он будет выглядеть сопоставимо на разных сенсорах [вывод].
2. Camera2 позволяет отключить шумодав и резкость даже на YUV — «натуральный» режим без RAW на многих устройствах. На iOS такого контроля нет.
3. Ниша на Android пустая: Dazz Cam, Huji, VSCO и подобные накладывают фильтр на уже обработанный JPEG. RAW-ориентированной «натуральной» камеры с профилями среди найденных нет [вывод по обзорам 2026].

## 4. Рекомендуемый стек [вывод]

- UI: Kotlin + Jetpack Compose (уже в проекте).
- Камера: CameraX 1.5+ с `Camera2Interop` для ручных параметров (NR/EDGE off, экспозиция); там, где не хватает, — прямой Camera2. Версию проверить на maven.google.com перед добавлением.
- Проявка и профили: OpenGL ES 3.1 compute shaders (поддержка шире, чем у Vulkan на старых устройствах). Профиль = 3D LUT (формат .cube) + параметрические зерно и halation.
- Хранение: MediaStore для JPEG/HEIC, DNG рядом; свой контейнер «RAW + параметры профиля» для повторной проявки.
- Монетизация: Google Play Billing.
- Референсы с открытым кодом: Open Camera (Camera2, DNG), Google `android/camera-samples` (RAW/DNG). MotionCam — проверить лицензию перед заимствованием.

## 5. Предлагаемый MVP

1. Камера: фото с основного модуля, RAW при поддержке, иначе YUV без NR/резкости.
2. 3–4 собственных профиля (не копировать профили и названия Lampa), превью-аппроксимация.
3. Проявка RAW на GPU → JPEG в галерею; повторная проявка другим профилем.
4. Галерея своих снимков.
5. Вне MVP: видео, Log, импорт, оплата.

Главный технический риск — качество и скорость RAW-пайплайна на GPU. Начать с прототипа проявки одного DNG.

## 6. Юридически

Не использовать название Lampa, иконку, UI и профили. Делаем собственный продукт с тем же принципом (RAW + профили без «ИИ»), а не клон.
